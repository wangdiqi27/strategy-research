# trix_vpt_research_v4

使用品种所有合约计算出的指数进行回测。

摒弃 VPT 指标， trix + vpt 指标双重确认，经常性导致趋势信号延迟很多。

该版本使用通道波动率压缩指标，来做趋势突破策略。trix 指标作为判断趋势是否反转的信号指标。


## 多头


### 开仓

1. 量价指标： 昨日价格上涨，成交量比14日平均成交量大 1.5 倍
2. trix指标：trix_hist diff > 0，且 trix_hist > 0，代表整体趋势看多
3. 通道指标:
   - 过去 20 天的最高点
   - 过去 20 天的最低点
   - 通道宽度=最高点 - 最低点
   - 通道压缩率=通道宽度 / daily_atr_20
   - 通道压缩率_20 = 过去 60 天通道压缩率的 20 值
   - 通道波动率是否压缩: 通道压缩率 < 通道压缩率_20，认为波动率已经很低
4. 通道波动率确认压缩至极值
5. TODO: 拐点

上面两个指标同时满足，允许今日做多


1. 今日开盘60分钟后
2. 今日最新1分钟K线 Close 价格突破通道上沿
3. 今日最新行情是上涨的:与今日开盘价比较

进行开仓

止损: max(通道低点, 入场价 - daily_atr_14 * 2)



### 平仓

1. 止损
2. 至少持仓7天 AND trix 指标反转： trix_hist diff < 0 AND trix_hist < 0，代表整体趋势看空
3. 最后一天可交易日

## trix_vpt_research_v10

v10 版本，基于 v9

## 平仓条件调整
1. 修改K线形态反转平仓逻辑
   - 原逻辑是看上一个交易日是否是一根巨型反转K线，如果是，则当日进行平仓
   - 修改后的逻辑是实时判断当日的K线形态，如果满足巨型反转K线条件，立刻平仓

## 结论

缺点：
1. 因为实时计算当日的K线形态时，由于行情并未走完，实体长度比例、上下影线的比例都是失真的。 
   如果行情中有比较多的长上影和长下影线，会导致提前退出趋势行情。这种情况下， 
   不如使用上一根K线形态来判断巨型K线的效果。在 ag、jd、MA 品种中效果比较差。
2. 一般发生巨型K线后，下一根K线很有可能有部分回调，放在第二天再平仓，影响也不是很大。

优点：
1. 如果确实发生了巨型K线反转，且不带回调的情况，这会帮助我们提前退出，减少损失。

分析原因
ag、jd、MA 收益大幅下滑分析：

ag 主要就是因为 2025-11-28 的一次开仓，v9版本吃到了比较大的趋势行情，v10版本因为当日K线形态
判断，2025-12-24 日有一条长下影线，导致日内判断时认为是一条巨型反转K线，但是其实收盘时已经不再是
大的实体K线

jd、MA 与 ag 类似

分析原因：
着重分析 3 倍的情况：
ag : 
1. 2025-11-28 开仓，2025-12-29 日被动态止盈止损，导致一个大的趋势没吃到，收益下降明显

# trix_vpt_research_v13

v13 版本，基于 v9

增加分形指标，识别 HH LH LL HL
- 左侧 bar 数量 L_N,右侧 bar 数量 R_N
- 当 bar.high 大于所有左侧和右侧的 bar.high，则为区间最高点
- 当 bar.low 小于所有左侧和右侧的 bar.low，则为区间最低点
- 识别 HH LH LL HL 结构

## 开仓条件
新增
- 不允许在 LH-LL 时开多单
- 不允许在 HH-HL 时开空单

## 平仓条件
新增
- 多单在识别到 LH-LL 时进行平仓
- 空单在识别到 HH-HL 时进行平仓

## 结论

对交易改善并不明显，当窗口大小选择为 [2, 4] 时，对品种的改善效果并不是一致的。

1. 因为分形指标不像zigzag指标，它的高低点并不是轮替出现的，
2. 而且，只要大于和小于左右两侧就认为是局部的高点和低点，
3. 这些原因导致高低点幅度变化并不大，但是却也被识别为 HH LH LL HL 结构


# trix_vpt_research_v14

v14 版本，基于 v9

增加 zigzag 指标，识别 HH LH LL HL
- 记录最新的高点和低点
- 如果最新的bar.low 与记录的最高点相差一个 threshold，则之前记录的最高点则被确认为最近的最高点 
- 如果最新的bar.high 与记录的最低点相差一个 threshold，则之前记录的最低点则被确认为最近的最低点
- 交替确认最高点和最低点
- threshold = atr * 1.5
- 识别 HH LH LL HL 结构

## 开仓条件
新增
- 不允许在 LH-LL 时开多单
- 不允许在 HH-HL 时开空单

## 平仓条件
新增
- 多单在识别到 LH-LL 时进行平仓
- 空单在识别到 HH-HL 时进行平仓

## 结论

与分形指标的不同点
- 高低点交替出现
- 使用波动率倍数来确认最近的高低点，使结构更明显。
  代价是，确定高低点时，不知道延时了多少根Bar，分形指标可以明确知道延时了窗口大小根 Bar。

对 lc、ag 收益有改进， MA 收益大幅降低

分析 MA 收益下降原因 
1. 主要缺点就是因为 zigzag 指标确认方式带来的:
   - 确认高低点需要反向运行超过一定幅度
   - 当前面还在识别成 LH-LL 时，最新的行情已经开始快速上涨，且不带回调，导致结构一直还是 LH-LL，
     因为不带回调，导致无法确认最新的高点


# trix_vpt_research_v15

v15 版本，基于 v14

主要是为了修改 zigzag 开平仓条件，因为 zigzag 的高低点确认机制，导致根据确认的高低点结构开仓会有问题，该版本主要解决这个问题。


## 开仓条件
新增
- 不允许在 LH-LL，且最新价格小于上一个确认高点时开多单：假设最新价成为未来的确认高点，如果大于上一个高点，则代表结构变化
- 不允许在 HH-HL，且最新价格大于上一个确认低点时开空单：假设最新价成为未来的确认低点，如果低于上一个低点，则代表结构变化

## 平仓条件
新增
- 多单在识别到 LH-LL，且最新价小于上一个确认高点时进行平仓
- 空单在识别到 HH-HL，且最新价大于上一个确认低点时进行平仓

## 结论

对某些zigzag极端情况有改善作用

# 详细描述

## 指标
1. trix指标：trix_hist diff > 0，且 trix_hist > 0，代表整体趋势看多
2. 通道指标:
   - 过去 20 天的最高点
   - 过去 20 天的最低点
   - 通道宽度=最高点 - 最低点
   - 通道压缩率=通道宽度 / daily_atr_20
   - 通道压缩率_20 = 过去 60 天通道压缩率的 20 值
   - 通道波动率是否压缩: 通道压缩率 < 通道压缩率_20，认为波动率已经很低 
3. 跳空判断
   - 当日开盘价跳空是否大于 1% 上一日收盘价
   - 上一日K线是否是跳空行情
4. K线形态判断
   - K线区间 High - Low
   - K线实体 abs(Close - Open)
   - K线方向，上涨 1，下跌 -1，不变 0
   - K线上影线比例
   - K线下影线比例
   - K线实体比例
   - 是否是巨型K线：K线区间大于过去60天的 90 分位值
5. trix 正负连续天数判断
   - 统计 trix 持续大于 0 的天数
   - 统计 trix 持续小于 0 的天数 
6. zigzag 结构指标识别 HH LH LL HL
   - 记录最新的高点和低点
   - 如果最新的bar.low 与记录的最高点相差一个 threshold，则之前记录的最高点则被确认为最近的最高点 
   - 如果最新的bar.high 与记录的最低点相差一个 threshold，则之前记录的最低点则被确认为最近的最低点
   - 交替确认最高点和最低点
   - threshold = atr * 1.5
   - 识别 HH LH LL HL 结构


## 多头开仓
1. 当前处于通道压缩
2. 最新1分钟收盘价大于通道高点 + 0.1 * daily_atr_14
3. 开盘30分钟后
4. 最新1分钟数据计算，当天是一根阳线
5. 不允许在 LH-LL，且最新价格小于上一个确认高点时开多单：假设最新价成为未来的确认高点，如果大于上一个高点，则代表结构变化


止损设置:
stop_loss = max(通道低点，开仓价 - daily_atr_14 * 2)

动态止盈止损设置
adjust_stop_loss = max(stop_loss, 持仓后的高点 * 0.8)   TODO: 最近的高点

## 多头平仓
1. 达到止损条件
2. 达到动态止盈止损条件
3. 当日开盘跳空反转达到 1%
4. 上一日是一个确认的跳空反转K线
5. 上一日是一个巨型反转K线
6. trix 反转，持仓大于 7 天，不处于通道压缩期，trix 小于0持续大于等于5天
7. 最后可交易日


## 空头开仓

1. 当前处于通道压缩
2. 最新1分钟收盘价大于通道低点 - 0.1 * daily_atr_14
3. 开盘30分钟后
4. 最新1分钟数据计算，当天是一根阴线
5. 不允许在 HH-HL，且最新价格大于上一个确认低点时开空单：假设最新价成为未来的确认低点，如果低于上一个低点，则代表结构变化

止损设置:
stop_loss = min(通道高点，开仓价 + daily_atr_14 * 2)

动态止盈止损设置
adjust_stop_loss = min(stop_loss, 持仓后的低点 * 1.2)

## 空头平仓
1. 达到止损条件
2. 达到动态止盈止损条件
3. 当日开盘跳空反转达到 1%
4. 上一日是一个确认的跳空反转K线
5. 上一日是一个巨型反转K线
6. trix 反转，持仓大于 7 天，不处于通道压缩期，trix 大于0持续大于等于5天
7. 最后可交易日

## 结论

lc收益率下滑，
FG、jd、MA 品种收益略增加，
ag 变化不大

从图表上看，减少了结构在很短时间开平仓的情况(由于zigzag的滞后性，导致开仓完，过一两天，结构就变化)，
看起来更合理。

## 新增指标

1. EMA40 状态统计
   - `ema40_above_days` / `ema40_below_days`：收盘价处于 EMA40 上方/下方的连续天数，离开该状态后归零
   - `ema40_cross_up` / `ema40_cross_down`：当日收盘价自下而上/自上而下穿越 EMA40（反转日标记）

- 状态机记录"资格周期最近一次被打断至今"的连续混合天数（`pack_mixed_run_days`）

  新鲜趋势环境下的确认破位不同

   且 EMA5 未反向穿越 EMA20 时，排列天数**冻结**（不累加不清零，"认为是连续的"），
   恢复排列后 run 从冻结值继续累加；持续 >= M 天则连续认定失败，run 与锚点清零重新积累
2. 锚点 = 环境（多头环境 = e5>e20）内**第一次**形成多头排列那天的价格；空头环境同理
3. 触发 = EMA5 反向穿越 EMA20：
   - 多头环境 EMA5 下穿 EMA20 → 做空候选；空头环境 EMA5 上穿 EMA20 → 做多候选
   - 触发日综合验证幅度 R（`ema_pack_min_price_change_pct`，除数为锚点价，分方向符号）：
     做空要求 (穿越价 - 锚点)/锚点 > +R；做多要求 < -R（v45 当前默认 0.0 = 启用拦截）
   - 破位即环境终结，被幅度门槛压制的信号不再重试（新一轮环境重新积累）
4. 结算顺序：触发判定（锚点=截至昨日）→ 幅度门槛 → 环境推进/清空；环境重进时 consumed 复位

实现注意：
1. 所有状态布尔值在存储前用 `bool()` 强转（历史 bug：numpy.bool_ 与 `is True`/`is False`
   的身份判断失效，导致生产环境从未发出信号——单元测试用 python 浮点数才侥幸通过）
2. 执行口径与全部版本一致：T-1 收盘确认、T 日盘中执行、开盘 30 分钟后、每交易日一次、压缩路径优先

## 平仓/开仓判定的配套机制（与信号口径解耦）

曾出现"机器信号正常但策略没开仓"的问题，两段因果：
1. 上述 numpy bool `is` 身份判断 bug（已修）
2. 策略持仓占位：压缩路径仓位开着时，信号日无法开仓，信号 flag 只活一天

据此修改开平仓规则（v45）：
1. **压缩路径持仓 + ema_pack 反向信号**（多头持仓遇 turn_down / 空头持仓遇 turn_up）：
   平仓并**立即反手开仓**（is_reverse_open 机制），反手单用排列口径止损（入场价 ± 2*ATR）、
   止盈 ± 3*ATR，open_reason = "ema_condition 反手 区间幅度 X%"
2. **ema_pack 路径持仓**遇反向信号：忽略，交由其余平仓条件处理
3. 实现配套：
   - 持仓来源用 open_reason 前缀识别（"channel_condition" / "ema_condition"，用户已引入；
     `_is_ema_pack_origin` 判断）
   - 移仓换月的再开仓改为 `{原open_reason}+移仓换月`，来源跨移仓保留
   - 顺带修正空头平仓块原有的 `if`/`if` 串联覆盖 bug（channel 反手 reason 会被止损覆盖），
     改为正常 elif 链
4. 逐日状态统计：每个交易日输出排列 run 天数、容忍 streak、锚点、信号/压制等
   （`{report_dir}/{symbol}-ema-pack-turn-state.csv`，排查"某天为何没开仓"用）
